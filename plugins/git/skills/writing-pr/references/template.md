# PR 本文のテンプレート

リポジトリに PR テンプレートがない場合に使う。「設計の要約」と「設計の理由」は必須。それ以外は、小さな PR では該当しないセクションを省いてよい。

```markdown
## 概要
<!-- 何を・なぜ変えるかを 1〜3 文で -->

Closes #

## 設計の要約
<!-- 必須。人間向け。どういう構成・仕組みにしたのかを短く。全体像が分かればよく、細部やファイルの列挙は不要 -->

## 設計の理由
<!-- 必須。あとから読む AI 向け。なぜこの設計にしたのか -->
- 選んだ理由・前提にした制約:
- 採用しなかった案とその理由:
- 意図的にやっていないこと・割り切り:
- 変更時に壊してはいけない前提:

## 変更内容
<!-- 主な変更点を箇条書きで。意味のある単位でまとめる -->
-

## 確認したこと
<!-- 実行したテストや動作確認と、その結果。マージ後に確認することは未チェックで残す -->
- [x]
- [ ]
```

## 書くときの注意

- 「設計の要約」は、PR を読んだ人間が「何がどう変わったのか」を説明できるようになる程度にまとめる。図やディレクトリツリーを使うと伝わりやすい。
- 「設計の理由」は、次にこのコードを触る AI が読む前提で書く。「なぜこうなっているのか」と疑問に思われそうな箇所を先回りして説明する。該当しない項目は省いてよいが、セクション自体は省かない。
- 「確認したこと」には、実行したコマンドや操作を具体的に書く（例: `npm test` が通る、記号入りパスワードでログインできる）。
- 破壊的変更、マイグレーション、設定変更など、マージやデプロイ時に注意が必要なことがあれば「概要」の直後に目立つように書く。
