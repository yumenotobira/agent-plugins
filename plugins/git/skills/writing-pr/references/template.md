# PR 本文のテンプレート

リポジトリに PR テンプレートがない場合に使う。「変更の要約」「前提」「変更の詳細」は必須。

```markdown
## 概要
<!-- 何を・なぜ変えるかを 1〜3 文で -->

Closes #

## 変更の要約
<!-- 必須。人間向け。何がどう変わったのかの全体像を短く。細部やファイルの列挙は不要 -->

## 前提
<!-- 必須。変更の前提になった制約。変更するときに守るべき要件、意図的にやっていないこと -->
-

## 変更の内容
<!-- 何を変えたかを、意味のある単位で箇条書きに -->
-

## 変更の詳細
<!-- 必須。AI 向け。「変更の内容」の各項目について、具体的な中身と、なぜそうしたか -->

### <変更の内容の項目>
- 内容:
- 理由:

## 確認したこと
<!-- 実行したテストや動作確認と、その結果。マージ後に確認することは未チェックで残す -->
- [x]
- [ ]
```

## 書くときの注意

- 「変更の要約」は、PR を読んだ人間が「何がどう変わったのか」を説明できるようになる程度にまとめる。
  - 処理の流れは番号付きの箇条書きで簡潔に書く。
  - ディレクトリ構成はツリーで書く。
- 「前提」には、判断の前提になった動かせない条件を書く。理由（判断）はここではなく「変更の詳細」に書く。
- 「変更の内容」と「変更の詳細」は項目を対応させる。「変更の内容」は一覧として人間も読み、「変更の詳細」は次にこのコードを触る AI が読む前提で、「なぜこうなっているのか」と疑問に思われそうな箇所を先回りして説明する。
- 「確認したこと」には、実行したコマンドや操作を具体的に書く（例: `npm test` が通る、記号入りパスワードでログインできる）。
- 破壊的変更、マイグレーション、設定変更など、マージやデプロイ時に注意が必要なことがあれば「概要」の直後に目立つように書く。
